## 2. 方法：为什么这次 BPM/拍号可信（而上一版自相关不可信）

| 项目        | 上一版（captain 已否）                                         | 本版                                                                                                                                                        |
| ----------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BPM         | numpy 自相关直接取峰                                           | **音强包络（spectral flux，log 幅度谱正向差分）→ DFT 速度显著度 + 2/3/4 次谐波加权 → 网格梳状对齐细调**                                                     |
| 倍/半速处理 | 无（这正是 4.7%–16.8% 偏差的来源）                             | 打印 **top-8 候选**并把"与官方 Tempo 的比值"一并列出（`1.000` / `2.000` 一眼可辨），再做 ±3 BPM 细调                                                        |
| 拍号        | 自相关周期直接判（把 `On the Shore` 判成 3/4，与官方描述矛盾） | **低频（40–250Hz）包络**上的节拍网格重音轮廓 → 2/3/4/6 拍各算"重音对比度 × 下拍稳定性"，并做**次谐波优先**（6/4 是 3/4 的两小节别名，分数接近时取更简单者） |
| 交叉核对    | 无                                                             | 与 Incompetech 官方 Tempo 对照；与官方描述（唯一的圆舞曲）对照                                                                                              |

原始输出（`python tools/library-analysis.py`，逐字复制）：

```text
── Immersed.mp3 ──
  细调后 BPM = 64.00（相位 429.7ms，梳状对齐得分 0.3546） → 相对官方 64 偏差 -0.00%
  拍号判定：4/4（低频重音轮廓；原始最优 4/4）· 与最强非谐波对手的边际 49.1% → 置信 HIGH · 谐波别名 {'2': 0.544}
── On the Shore.mp3 ──
  细调后 BPM = 84.41（相位 651.6ms，梳状对齐得分 0.2040） → 相对官方 82 偏差 +2.94%
  拍号判定：4/4（低频重音轮廓；原始最优 4/4）· 与最强非谐波对手的边际 33.7% → 置信 HIGH · 谐波别名 {'2': 0.896}
── Rains Will Fall.mp3 ──
  细调后 BPM = 84.99（相位 647.1ms，梳状对齐得分 0.5801） → 相对官方 85 偏差 -0.01%
  · 次谐波优先：3/4 得分 2.313 ≥ 0.85×最优(6/4 2.534)，且 6 是它的整数倍 → 取更简单的 3/4
  拍号判定：3/4（低频重音轮廓；原始最优 6/4）· 与最强非谐波对手的边际 86.6% → 置信 HIGH · 谐波别名 {'6': 2.534}
```

**结论与诚实边界**：

- **两首与官方 Tempo 偏差 ≤0.01%**（64.00 / 84.99）；`On the Shore` 实测 **84.41 对官方 82（+2.94%）** —— 明显大于前两首，
  可能是元数据取整、也可能是我这版检测在该曲上有残余偏差，**如实记录**；
  **它对本次交付无影响**：分段法**与拍号/BPM 无关**（边界吸附到起音），BPM 只用于显示与 `startBar/barCount` 参考。
- **拍号**：`Rains Will Fall = 3/4`（圆舞曲，与官方描述一致）、另两首 `4/4`（其中 `On the Shore` 恰恰是被上一版错误判成 3/4 的那首）。
  每首都给了"与最强非谐波对手的边际"与谐波别名分数，**可被复核、可被证伪**。
- 拍号仍属**推断**：最终以**用户听感**为准（§7）。

## 3. 分段表（候选，待用户听感确认）

方法（§19.2）：目标段长 `T≈22.5s` → 边界 `0, T, 2T, 3T, 4T` → 每个内部边界在 **±1.5s** 窗口内吸附到**最强起音** →
记录起音强度与全曲分位；段长必须落在 [15,30]，越界则收紧窗口重算（本轮 ±1.5s 即通过，未触发收紧）。

| 曲目            | 段  | start  | end    | 时长(s) | 边界起音强度 | 全曲分位 | 判定 |
| --------------- | --- | ------ | ------ | ------- | ------------ | -------- | ---- |
| Immersed        | 1   | 0.000  | 23.870 | 23.87   | —            | —        | 起点 |
|                 | 2   | 23.870 | 44.489 | 20.62   | 5.2884       | 100.0    | 显著 |
|                 | 3   | 44.489 | 66.990 | 22.50   | 2.0942       | 99.8     | 显著 |
|                 | 4   | 66.990 | 90.000 | 23.01   | 1.3779       | 99.4     | 显著 |
| Rains Will Fall | 1   | 0.000  | 21.850 | 21.85   | —            | —        | 起点 |
|                 | 2   | 21.850 | 44.420 | 22.57   | 1.3197       | 99.7     | 显著 |
|                 | 3   | 44.420 | 67.733 | 23.31   | 0.8701       | 98.5     | 显著 |
|                 | 4   | 67.733 | 90.000 | 22.27   | 1.2543       | 99.7     | 显著 |
| On the Shore    | 1   | 0.000  | 22.709 | 22.71   | —            | —        | 起点 |
|                 | 2   | 22.709 | 44.164 | 21.45   | 3.5555       | 100.0    | 显著 |
|                 | 3   | 44.164 | 67.988 | 23.82   | 1.0764       | 99.1     | 显著 |
|                 | 4   | 67.988 | 90.000 | 22.01   | 0.3383       | 94.8     | 显著 |

- 三首**总长都是 90.00s**（落在 CONTEXT §3.1 的 60–120s 内），每段都落在 15–30s 内。
- "显著"判据 = 起音强度 ≥ 全曲 60 分位 **且** ≥ 窗口内 P90 的 1.2 倍 **且** ≥ 0.02 绝对下限
  （**不用中位数**：包络半波整流后大量帧为 0，中位数恒为 0 会让判定退化成"永远通过"）。
- 本轮 9 个内部边界**全部显著**；若将来某边界不显著，`library.json` 会标 `significant: false`，
  **入库脚本默认拒绝写库**（`packages/shared/src/audio/library.test.ts` 有测试钉住这条门禁）。

## 4. 响度归一（只用增益，不做限幅）

ITU-R BS.1770-4（K 加权 + 门限积分响度，48kHz 系数）+ 样本峰值：

| 曲目            | 积分响度    | 样本峰值   | 归一增益     | 归一后响度  | 归一后峰值 |
| --------------- | ----------- | ---------- | ------------ | ----------- | ---------- |
| Immersed        | −27.69 LUFS | −8.04 dBFS | **+2.96 dB** | −24.73 LUFS | −5.08 dBFS |
| On the Shore    | −22.82 LUFS | −4.92 dBFS | **−1.91 dB** | −24.73 LUFS | −6.83 dBFS |
| Rains Will Fall | −26.66 LUFS | −2.93 dBFS | **+1.93 dB** | −24.73 LUFS | −1.00 dBFS |

**为什么目标不是"常见"的 −16 LUFS**：逐首打到 −16 会让**三首都顶破峰值上限**（需要限幅/压缩），
而限幅会改动 CC BY 素材的动态。因此取「**在峰值上限 −1 dBFS 约束下三首都能达到的最大等响目标**」：

```text
maxSafeEqualLoudnessLufs = min_i( LUFS_i + ceiling − peak_i ) = −24.73 LUFS
```

这样**三首等响、无削波、零信号处理**（只用增益）。若将来想要更响，两条可选路径（需用户/ captain 决定）：
① 允许轻量限幅；② 在播放端再叠加主音量（Web Audio 32-bit float 图内无害）。

## 5. 入库（幂等 + 两道闸门）

```bash
# 只校验（不需要数据库；CI/评审可跑）
pnpm --filter @music-drift/api exec tsx src/audio/library-cli.ts --check

# 真正入库（需 DATABASE_URL 与已跑迁移）
pnpm db:up
pnpm --filter @music-drift/api exec tsx src/audio/library-cli.ts

# 用户听感确认通过后才允许放行"起音不显著"的边界
pnpm --filter @music-drift/api exec tsx src/audio/library-cli.ts --allow-unreviewed
```

- **闸门 1**：`validateSegmentTable`（段号连续、边界相接、每段 15–30s、总长 60–120s、时长自洽）不过 → 抛错、**零写入**；
- **闸门 2**：存在 `significant: false` 的边界 → **默认拒绝入库**（§19.4 的"不得自行定稿"落成代码）；
- **id 方案与 `db/seed.ts` 一致**：`songId` 复用 seed 的固定 UUID，段落 id = `00000000-0000-4000-900<序号>-<段号12位>`。
  因此入库是「**占位歌换真歌**」：已存在的瓶子外键不断、`on conflict (id)` 不堆重复行，
  且 `licensed_source` 从 `placeholder` 变为 `incompetech-cc-by-4.0` 后 **re-seed 不会覆盖真曲目**（有集成测试）。
- ⚠️ **已知限制**：该 id 方案把序号写进 UUID 分组，**只有 1..9 合法**（两位数会产出非法 UUID —— 这是集成测试真实撞到的 bug）。
  因此 `segmentRowId` **主动拒绝**越界序号；曲库要扩到 10 首以上时，seed 与 ingest 必须一起换派生方案（一次性迁移）。

## 6. 伴奏播放：只播当前段（§19.3）

`useAccompaniment({ track, segmentIndex })`：

- 进入某段时把播放头摆到 `startMs`；`timeupdate` 上判定 `currentTime ≥ endMs` → **暂停 + 回到段首**并回调 `onSegmentEnded`
  （不越界播到下一段，也不停在半路）；
- **响度归一增益走 Web Audio `GainNode`**：三首增益有正有负（+2.96 / −1.91 / +1.93 dB），
  `HTMLMediaElement.volume` 只能衰减到 0..1，**表达不了正增益**；
- 段号来自服务端 `nextRecordIndex`（前端不推算），与 t8 混音的时间槽使用**同一个 `segmentIndex`**。
