TDD 证据（红 → 绿）：

- 基础层（路由表 / 错误文案 / 契约客户端 / 本机索引）：先跑测试 → `Failed to resolve import "./routes"` 等 **4 个文件 0 测试通过** → 实现后 **32 测试全绿**。
- 组件与页面层：**12 个文件**因模块未实现而红（`Failed to resolve import "../bottle-page"` 等）→ 实现后全绿。
- 过程中测试抓到 **3 个真实缺陷**（不是"测试写错"）：
  1. **账号错误 envelope 解析丢失**：`AUTH_ERROR_CODES` 不在领域词表里，只按 `ErrorResponseSchema` 解析时
     `/api/auth/*` 的 409/422 会**丢掉 code**，页面只能说"请先登录"而不是"这个邮箱已经注册过了"。
     修法：同时尝试 `AuthErrorResponseSchema`（两个 envelope 同形）。回归测试已加。
  2. `URL.createObjectURL` 在受限环境（jsdom / 部分 WKWebView）存在但不可用，会让**整页崩掉**；
     本地回放改为容错（失败就只是没有回放，不影响上传重试）。
  3. 未登录时页面仍摆出「录制 / 放回海中」按钮（点了必然 401）；改为 `session.status === 'authed'` 才展示，
     未登录只给登录出口。另外会话接口 5xx 与"确实没登录"分开呈现（否则会把服务器故障说成"你需要登录"）。

## 3. 真实链路验证（真库 + 真 HTTP + 真音频字节）

> ⚠️ **可复现性更正（captain 复核发现，已开 t19 修复）**：本文档早先声称"26 步全过"是**不成立的证据**。
>
> 1. 脚本**非 hermetic**：河道里混着其他测试残留的瓶子时，随机捞取会返回**别人的瓶子**，第 15 步起会连锁失败 ——
>    一次"全过"取决于环境运气，不构成可复现证明（ADR-019「测量不得自我印证」）。
> 2. 下文命令里的 `DATABASE_URL=…` 是**手工绕过**：`apps/api` 的 `start` / `dev` 脚本**不加载 `.env`**，
>    照 README 直接 `pnpm start` 会得到"DB 路由全不挂、`/api/songs` 404"（captain 首次复现即撞上；我没回溯到 `start` 脚本，属漏报）。
> 3. 结论：**在本文件里，"26 步通过"只作为"当时环境下的观察"**；可复现版本由 **t19**（`.env` 加载 +
>    live-check hermetic 化 + `GET /api/me/bottles`）交付后再作为验收证据。

脚本：`apps/web/tools/golden-path-live-check.mjs`（可复跑）

```bash
pnpm db:up && pnpm db:migrate && pnpm db:seed
cd apps/api && DATABASE_URL=postgres://music_drift:music_drift_dev@localhost:5433/music_drift npx tsx src/server.ts &
node apps/web/tools/golden-path-live-check.mjs
```

## 4. 需要人在浏览器里确认的部分（验收清单）

前置：`pnpm db:up && pnpm db:migrate && pnpm db:seed && pnpm dev`，浏览器开 **http://localhost:5173**（录音只在 `https` 或 `localhost` 可用）。

两个窗口（普通窗口 + 隐身窗口，或两个浏览器）各登录一个账号，按顺序走：

| #   | 操作（窗口 A / 窗口 B）                                                     | 期望看到                                                                              |
| --- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1   | A：打开 `/login` → 注册一个账号                                             | 注册成功即进入下一步；页脚与卡片文案为中文，无破图                                    |
| 2   | A：点「选一首歌，投出第一棒」→ 选一首 → 授权麦克风 → 录 15–30 秒 → 用这一段 | 「已录下第 1 段」的播报（`aria-live`）+ 自动弹出「选择声音去向」                      |
| 3   | A：选「继续投河」→ 确认投递                                                 | 回到详情页并播报「已投河」；面包屑状态胶囊变为「在河道」                              |
| 4   | B：登录另一个账号 → 进 `/river` → 点「捞一个漂流瓶」                        | 直接进入这支瓶子；左侧接力时间轴显示「第 1 段」+「缺第 2、3、4 段」                   |
| 5   | B：试听第 1 段 → 录第 2 段 → 用这一段                                       | 试听有进度文字（"已听 x 秒 / 共 y 秒"），不依赖波形颜色                               |
| 6   | B：去向三选一                                                               | 三张卡各自说明"会发生什么"；未选时「确认投递」为禁用态                                |
| 7   | 两人轮流把 4 段补满（需要 3–4 个账号，因为"唱过的人不会再捞到同一支"）      | 每段都落在**服务端给的段号**上；缺口文案随实际缺口变化                                |
| 8   | 末段录完                                                                    | 「继续投河」消失，只剩「回传 / 入海」（CONTEXT §4.3）                                 |
| 9   | 选「回传」                                                                  | 瓶子回到上一棒手里（换窗口打开这支队，看「你的这一步」区域变化）                      |
| 10  | 持有者选「入海」                                                            | 公海「完整作品」出现这支作品；`/sea/:id` 有分段试听 + 成品（阶段一 · 纯人声）导出面板 |
| 11  | 任一窗口打开 `/bottles/:id/log`                                             | 时间线按 `seq` 升序，系统行为显示「系统」，不出现英文事件码                           |
| 12  | 任一窗口打开 `/me`、`/settings`                                             | 身份、匿名代号、本机记录的瓶子；登出后回到登录页                                      |

**每页都要看的两件事**：① 375px（DevTools 设备栏 iPhone SE）无横向滚动条；
② 1440px 下侧栏 + 内容不挤压、卡片不重叠。桌面导航用侧栏高亮，窄屏折叠为底部四项导航（触控目标 ≥44px）。
